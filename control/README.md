# SmartCiti.X : Trade Craft Academy — Control Plane v2.0

The deterministic half of the Adaptive Stack (ACP-02/03/04/05/06/07/15) as running
code, plus the simulations that calibrated it. Zero dependencies, ESM, Node 18+.

```
lpa.mjs        ACP-02  Learner Profile Agent — Elo co-update, BKT, sigma, decay, velocity
dial.mjs       ACP-03  the ZPD dial (closed loop + affect steps) and ACP-07 affect classifier
graph.mjs      ACP-15  skill graph — credit propagation, readiness, interference, diagnosis
sequencer.mjs  ACP-05  next-task policy — working set, review, verification, wheel-spin
gates.mjs      ACP-06  assessment gates and anti-gaming detectors
simulate.mjs           six learner archetypes x three strategies, seeded and reproducible
sweep.mjs              parameter sweep over window x loopGain
sim_curriculum.mjs     graph sequencing vs blocked/flat curricula
test.mjs               12 checks, including end-to-end against the module registry pack
test_graph.mjs         20 checks — graph tracing, sequencing, gates
soak.mjs               long-run invariant soak (default 4,000 attempts x 3 seeds)
```

## Run it

```bash
node test.mjs        # 12 checks — wire this into CI
node test_graph.mjs  # 20 checks — graph, sequencer, gates
node soak.mjs        # long-run invariants; `node soak.mjs 10000` to push it
node simulate.mjs    # the calibration table
node sweep.mjs       # the 20-configuration parameter sweep
```

`test.mjs` imports the module registry from `../pack/registry`, so keep the two
packs as siblings (or edit the import).

## Design notes that matter

**The control plane has no LLM in it, deliberately.** Every number here is
arithmetic. That is what makes a dial decision auditable, sub-millisecond, and
testable — and it is why the mentor agents are read-only consumers of dial state
rather than participants in it.

**The dial is closed-loop as of v1.2.** Open-loop stepping bounded relative to θ
cannot correct a systematically biased θ; the controller now inverts the logistic
on the observed success rate to find the difficulty that would have hit the band
centre, and moves a damped fraction of the way there. The affect logic still
decides whether to sit above or below the band.

**`startSession()` is load-bearing.** The session cap is anchored there. A dial
that never re-anchors freezes ±10 points from wherever it started, which is how
the v1.1 bug served a much-improved learner beginner tasks for 300 attempts.
There is a regression test that fails if that requirement is quietly removed.

**All clamping happens in `setpoint()`**, in one order: θ rail (safety), then
session cap (experience), session cap wins on conflict. Two clamp sites with
different anchors was defect 2.

## Calibrated defaults

| Parameter | Value | Source |
|---|---|---|
| target band | [0.70, 0.85] | pedagogy |
| setpointOffset | θ − 6.5 (p ≈ 0.777) | logistic inversion |
| window | 5 attempts | sweep — responsiveness over 2.3 points of residency |
| loopGain | 0.3 | sweep |
| rails | θ−14 … θ+0 | sweep (old rails bound during normal operation) |
| stepDown / stepUp | 4 / 2+velocity | pedagogy (down faster than up) |
| B_hi / A_hi | 0.6 / 0.6 | affect |

## Results summary

Mean in-band residency: **dial 39.8%**, fixed difficulty 6.1%, random 7.0%. All
six archetypes finish with mean success inside the 70–85% band; θ tracking error
0.9–3.6 points against up to 18.5 for the baselines. Full method, caveats and the
sweep table are in ACP-14 of the spec.

**What this does not prove.** It validates the controller, not the pedagogy. The
affect signals were generated by the same model that consumed them, which is
circular and is the weakest part of the exercise. Shadow mode on real telemetry —
dial logging intended actions, acting on none — is still a required gate.

## Not implemented here

The sequencer's full scoring (ACP-05 §5.2), the hint ladder's content, assessment
gates (ACP-06) and everything in ACP-08 beyond the rails. The registry pack's
`selectForDial()` provides candidate eligibility; scoring belongs in the sequencer.
