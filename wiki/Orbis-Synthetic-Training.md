# Orbis synthetic-training prompts

shaped to hand to the ml-agents fork RECORDED in meta/registry/metaverse already gets a real,
schematic episode log from `training/`. This pack adds a second, separate
stream: a deterministic PROMPT CONTRACT that turns any of the
111 union modules into a text prompt for a hosted
text/image-to-video model, so an operator who wants denser synthetic video
for robotics-training augmentation can generate it themselves — for any
module, whether or not a learner has ever trained there.

## What this build does not do

this build reaches no host outside GitHub, and the page it extends calls no network host at all: it builds prompt text locally and stops - generating an actual clip happens outside this bundle, on the operator's own Orbis deployment

this bundle never requests, stores or transmits a REACTOR_API_KEY or a GEMINI_API_KEY. running the sequence above against a real prompt is the operator's own action, with their own keys, against the cited public API - this pack declares the contract, it does not exercise it

## The prompt template

Built from the union registry already shipped elsewhere in this bundle —
no fact is authored twice:

```
A {district} apprentice practicing {hall}: {focus}. Training-yard setting, full PPE visible, single continuous take, documentary style, no on-screen text.
```

## The command sequence (RECORDED from the cited README)

1. POST /api/token mints a scoped session JWT from the token endpoint
2. connect to the model with recv-only main_video and main_audio tracks
3. read the state snapshot; treat its available_resolutions as authoritative
4. set_image (optional) to supply a reference frame before start
5. set_resolution (optional) to stage a delivery tier for the next start
6. set_prompt (required) supplies the prompt text this pack builds
7. start begins generation; another set_prompt steers it mid-run
8. pause / resume / reset control an active generation

Chunking: chunks emit roughly every 1.8 seconds; the first chunk carries no frames while the upscaler primes

## What a generated clip is not

a clip generated from one of these prompts is AI-SYNTHESIZED synthetic video - it is not footage of any real trade, worker or site, and it is a separate stream from the real, schematic episode log training/ already records from a learner's own interactions

the prompt builder works from the union registry, not the training log, so every one of the 111 modules has a prompt whether or not a learner has ever trained there

**Verified from build:** False. this build reaches no host outside GitHub and npm/pypi, so the contract above is carried as RECORDED from the cited README rather than re-checked against Reactor's live API on every build

## A second, separate thing: two real runners

Everything above is text only. Two directories are different - real,
runnable companion apps, each scaffolded from Reactor's own
`create-reactor-app` templates and each wired to the same generated
scene library so all 111 modules show up as presets
rather than a template's illustrative demo scenes:

- **`orbis/runner-helios/`** — model `reactor/helios`, scaffolded from `create-reactor-app --model=helios` (github.com/reactor-team/create-reactor-app (templates/helios), Apache-2.0). Run it: `cd orbis/runner-helios && cp .env.example .env.local && # put a REACTOR_API_KEY you generated yourself into .env.local && pnpm install && pnpm dev`
- **`orbis/runner-visko-orbis-stable/`** — model `reactor/visko-orbis-stable`, scaffolded from `create-reactor-app --model=visko-orbis-stable` (github.com/reactor-team/create-reactor-app (templates/visko-orbis-stable), Apache-2.0). Run it: `cd orbis/runner-visko-orbis-stable && cp .env.example .env.local && # put a REACTOR_API_KEY you generated yourself into .env.local && pnpm install && pnpm dev`

Both draw `app/lib/modules.generated.json` from the same union
registry this whole pack comes from - one source of truth, two
consumers. Neither runner is ever installed, started, or given a key by
this repository's own build or verify pipeline; each is a real Next.js
app an operator runs themselves, with their own REACTOR_API_KEY, on
their own machine.
